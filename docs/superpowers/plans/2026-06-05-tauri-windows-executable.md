# Tauri Windows Executable Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the current incomplete Electron-based Windows packaging path with a working Tauri-based Windows executable workflow for this React + TypeScript + Vite app while preserving the existing Android Capacitor path.

**Architecture:** Add a standard Tauri v2 wrapper in `src-tauri/` and wire it to the existing Vite build output in `dist/`. Keep the web app as the single UI codebase, keep Capacitor for Android, and avoid desktop-specific frontend changes unless verification proves they are necessary.

**Tech Stack:** React 18, TypeScript 5, Vite 6, Vitest, Tauri 2, Rust/MSVC toolchain, Windows WebView2

---

## Decision Gate

The implementation can start with these assumptions, but the owner should confirm them before Task 3:

1. Windows packaging should move to **Tauri only**, and the incomplete Electron path should be removed instead of maintained in parallel.
2. The first Windows deliverable should be an **installer** rather than a portable single executable.
3. The Windows app identity should use the user-facing name **Personal Learning Assistant** and a desktop app ID aligned with the current package identity, for example `com.carot.personal-learning-assistant`.
4. Desktop file import should use the existing browser/web picker path first; no Tauri file-dialog plugin should be added unless a real limitation appears during verification.

If any of these assumptions are wrong, stop after Task 2 and update the plan before coding.

## File Structure

**Create**
- `src-tauri/Cargo.toml` — Rust package metadata and Tauri crate dependencies.
- `src-tauri/build.rs` — Tauri build script generated by the CLI.
- `src-tauri/src/main.rs` — Desktop app entry point that launches the Tauri shell.
- `src-tauri/tauri.conf.json` — Tauri app configuration, build hooks, bundle targets, window title, icons, and frontend wiring.
- `src-tauri/capabilities/default.json` — Minimal capability file if generated by the Tauri v2 init flow.
- `src-tauri/icons/*` — App icons used by the Windows bundle.
- `docs/diataxis/how-to/build-windows-tauri.md` — End-user build instructions for the Windows executable path.

**Modify**
- `package.json` — Remove Electron packaging scripts and add Tauri scripts and dev dependencies.
- `package-lock.json` — Lockfile updates after dependency changes.
- `README.md` — Replace Electron packaging commands and directory references with Tauri equivalents.
- `AGENTS.md` — Update the project command table and packaging notes so the repo instructions stay correct.
- `src/App.tsx` — Only if verification shows the current router selection is not sufficient under Tauri.
- `src/services/fileService.ts` — Only if verification shows Tauri needs an explicit desktop-native file picker path.

**Verify**
- `vite.config.ts` — Confirm `base: './'` and `dist` output remain compatible with Tauri.
- `capacitor.config.ts` — Confirm Android remains unchanged and still points to `dist/`.
- `src/services/fileService.test.ts` — Extend tests only if desktop-specific file import logic is introduced.
- `src/App.test.tsx` — Extend tests only if router selection logic changes.
